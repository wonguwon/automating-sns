# 작업 계획

이 커맨드는 조사와 제안까지만 한다. 사용자가 명시적으로 승인하기 전에는 코드를 구현하거나 파일을 수정하지 않는다.

## 입력

이번 개발 목표: $ARGUMENTS

목표가 비어 있거나 너무 모호하면, 조사를 시작하기 전에 사용자에게 목표를 구체적으로 물어본다.

## 할 일

1. **탐색 — 특정 파일명을 미리 전제하지 않는다.** 기존 이름은 예시일 뿐이며 프로젝트 구조가 바뀌었을 수 있다. 매번 실제 저장소를 다시 탐색한다.
   - Glob/Grep으로 목표와 관련된 키워드·기능을 찾는다.
   - 프로젝트의 실제 진입점(예: 실행 스크립트, 앱 엔트리포인트)부터 시작해 호출 관계를 따라가며 관련 모듈을 확인한다.
   - 관련 설정 파일(환경변수, 의존성 목록 등)과 기존 테스트가 있는지 확인한다.
   - 탐색으로 실제 존재를 확인한 파일만 근거로 삼는다. 존재를 확인하지 않은 파일명을 계획에 넣지 않는다.
2. `wiki/decisions.md`를 읽고 이번 목표가 기존 확정 결정과 충돌하지 않는지 확인한다. 충돌하면 구현 방향을 결정하기 전에 사용자에게 알린다.
3. CLAUDE.md의 작업 범위 원칙을 지킨다.
   - 요청 범위 밖의 대규모 리팩터링을 제안하지 않는다.
   - 확인하지 않은 기능이 이미 작동한다고 가정하지 않는다.
4. 다음 형식으로 계획을 제안한다.
   - **변경할 파일 목록** (탐색으로 확인한 실제 경로만)
   - **구현 순서** (단계별)
   - **각 단계의 검증 방법** (무엇을 어떻게 실행/테스트해서 확인할지 — 아직 실행하지 않은 것은 "예정"으로 표시)

## 제약

- 사용자가 계획을 명시적으로 승인하기 전에는 코드나 파일을 수정하지 않는다.
- 실행하지 않은 테스트를 통과했다고 말하지 않는다.
- API 키와 환경변수 값을 계획이나 응답에 노출하지 않는다.
