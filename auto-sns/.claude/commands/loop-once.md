wiki/current.md와 wiki/roadmap.md를 기준으로 작업 루프를 1회 실행해줘.

## 루프 절차

1. `wiki/context.md`, `wiki/current.md`, `wiki/decisions.md`, `wiki/roadmap.md`를 읽는다.
2. 현재 상태와 가장 앞의 미완료 작업을 파악한다.
3. 이번 루프에서 끝낼 수 있는 작은 작업 1개만 선택한다.
4. 짧은 계획을 작성한다.
5. 기존 결정과 충돌하지 않으면 바로 실행한다.
6. 실행 후 검증한다.
7. `wiki/current.md`를 갱신한다.
8. 완료된 항목이 있으면 `wiki/roadmap.md`를 갱신한다.
9. 필요하면 `wiki/decisions.md`, `wiki/retrospective.md`, `wiki/work-log.md`를 갱신한다.
10. session-end 형식으로 보고한다.

## 승인 없이 진행 가능한 작업

- auto-sns 내부의 새 파일/폴더 생성
- 문서 작성/갱신
- services/core 골격 작성
- legacy 파일 복사
- 기존 결정에 부합하는 작은 코드 정리
- 로컬 문법 검사/테스트 실행

## 반드시 멈추고 사용자 확인이 필요한 작업

- 기존 v3 프로젝트 수정
- 파일 삭제 또는 대량 이동
- 의존성 설치
- 외부 네트워크/API 호출
- Docker 배포/서비스 실행
- DB 스키마 방향 변경
- 기존 decisions.md와 충돌하는 변경
- 한 루프 범위를 넘는 대규모 구현

## 종료 조건

아래 상황이면 작업을 멈춘다.

- 사용자 결정이 필요한 경우
- 테스트/검증이 실패한 경우
- 기존 결정과 충돌하는 경우
- 파일 삭제, 대규모 이동, 외부 설치, 배포 작업이 필요한 경우
- 작업 범위가 한 루프를 넘는다고 판단되는 경우

## 제약

- 한 번에 작업 1개만 처리한다.
- 기존 v3 프로젝트는 수정하지 않는다.
- auto-sns 폴더 안에서만 작업한다.
- 요청 범위 밖의 대규모 리팩터링은 하지 않는다.
- 대용량 산출물, mp4, png 결과물, data 실행 결과는 복사하지 않는다.
- API 키와 환경변수 값은 출력하지 않는다.
- 실패하면 억지로 다음 작업으로 넘어가지 말고 `wiki/current.md`에 blocked 상태와 다음 조치를 남긴다.
