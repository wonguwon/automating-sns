# Retrospective

V3 개발이 완료되고 V4로 넘어가는 시점에 작성한다. (2026-07-31 작성 — V4는
상위 폴더의 새 프로젝트 `auto-sns`로 시작했다.)

## V3에서 해결하려던 문제

- V2까지의 완전 자동화 파이프라인 구조의 한계를 반영해, 사람이 각 단계 결과를
  확인하고 넘어가는 반자동화로 새로 설계하는 것(`wiki/context.md` "버전 관계").
  다만 V2의 어떤 지점이 구체적으로 문제였는지는 위키에 상세히 기록돼 있지
  않다 — 방향 전환의 결론만 남아 있다.
- 순차 "단계" UI 대신, 파이프라인 각 단계를 파일(문서) 기반으로 독립 실행
  가능하게 만드는 것(`data/pipeline/<id>.json` 매니페스트로 단계 간 연결).

## 실제로 잘 된 것

- 문서 기반 독립 실행 구조가 실제로 동작했다 — 컨텐츠 수집·딥리서치·카드뉴스
  제작·릴스 제작 각 페이지의 하위 섹션이 파일로 연결되어, 이전 단계를 같은
  세션에서 이어가지 않아도 원하는 단계부터 바로 실행할 수 있었다.
- 5개 페이지(컨텐츠 수집/딥리서치/카드뉴스 제작/템플릿 관리/릴스 제작)를
  실제 소재로 전 구간(수집→선별→딥리서치→JSON→이미지→렌더→캡션, 그리고
  대본→장면 이미지→TTS→조립) 실행까지 검증했다.
- 외부 API 통합(OpenAI, Volcengine Ark Seedream, 타입캐스트 TTS, 로컬
  ffmpeg, playwright 렌더)이 전부 실사용까지 검증됐다.
- 저작권 안전장치(원문 재사용 금지, 직접 인용 시 따옴표+화자 표기, 출처
  유지)를 딥리서치·카드뉴스 JSON·인스타 캡션 프롬프트 전반에 일관되게
  반영했다.
- 실측 기반 튜닝(릴스 레터박스 수치, 폰트 크기, 대본 분량 기준을 "줄 수"에서
  "글자수"로 변경)이 실제 문제(ffmpeg `drawtext`의 `%` 소실 버그 등)를
  찾아내고 고치는 데 도움이 됐다.

## 실제로 안 됐던 것 / 한계

- Streamlit이라는 선택 자체가 결국 한계였다 — 여러 사용자 동시 사용, 권한
  관리, 긴 작업(이미지 생성·렌더·TTS)을 브라우저 세션에 묶이지 않고 추적하는
  것을 처음부터 다루기 어려운 구조였다. 이번 V4 전환(React+Spring
  Boot+MySQL+Python Worker)의 직접적인 동기다.
- `pipeline_common.py`에 UI 헬퍼(`st.error`/`st.dialog`/`st.session_state`
  기반 위젯)와 순수 비즈니스 로직(프롬프트 조립, API 호출, 경로 상수)이
  한 파일에 섞여 있었다 — `auto-sns`로 로직을 옮기며 실제로 분리가 필요함을
  확인했다(services 계층에 "Streamlit을 import하지 않는다" 원칙을 명시한
  이유).
- 아래 항목은 끝내 결정/구현하지 못하고 V4로 넘어간다(`wiki/context.md`,
  `wiki/roadmap.md` "아직 결정하지 않은 사항"):
  - 루트 `sources.json`/`Research.py`, `Generate.py`의 CLI(`main`) 경로 —
    고아 상태로 정리하지 못했다.
  - `history.json` 기록은 2026-07-28부터 계속 꺼둔 채였고, 데이터 구조
    재설계도 하지 못했다.
  - `data` 폴더 구조의 최종 형태, 콘텐츠 중복 판정 방식.
  - 인스타 캡션을 파일로 저장할지(끝까지 세션에만 유지).
  - 릴스 세부 튜닝 — 타입캐스트 목소리는 "민욱" 고정으로 끝났고(선택 UI
    없음), 릴스 사진 라이브러리 관리 페이지는 만들지 못했으며, 감정/속도
    프리셋도 다듬지 못했다.
  - 루트 `README.md`는 V2 문서 그대로 갱신하지 못했다.

## V2와 비교해 달라진 점

- 순차 단계 UI → 문서(파일) 기반 독립 실행 + 명시적 「선택」 버튼으로 확정.
- 콘텐츠 ID를 사람이 입력하지 않고 GPT 선별이 만든 후보 id(`YYYYMMDD-NN`)를
  그대로 파이프라인 식별자로 사용.
- 딥리서치가 실제 웹 검색을 하지 않고, GPT 선별 시 모은 원문 링크를 그대로
  읽어 근거를 보강하는 방식으로 바뀜(정확성 리스크 회피).
- 소스(피드) 관리가 그룹 단위(`sources/*.json`)로 바뀌고 GPT 자동 제안 +
  헬스체크가 추가됨.
- 카드뉴스 스토리라인이 고정 흐름 강제 대신 "사실·형식 고정, 스토리라인은
  GPT 재량 + 선택적 콘텐츠 방향 입력"으로 바뀜.
- 저작권 안전장치가 프롬프트 차원에서 명시적으로 추가됨.
- 카드뉴스에 더해 릴스(나레이션 단독 대본 + TTS + zoompan 조립)가 새로
  추가됨.

## V4에서 다시 검토해야 할 것

- `pipeline_common.py`처럼 UI와 로직이 한 파일에 섞이는 구조를 처음부터
  피한다 — `auto-sns`의 services 계층 원칙(Streamlit/DB를 직접 모름, DTO
  input/output)으로 강제한다.
- V3에서 미뤄뒀던 `data`/`history` 구조 결정을 MySQL 스키마 설계(jobs 테이블
  포함) 시점에 함께 확정한다.
- V3에서 못 만든 기능(TTS 목소리 선택, 릴스 사진 라이브러리 관리 페이지,
  인스타 캡션 저장 여부)을 V4 화면/API 설계에 포함할지 결정한다.
- 여러 사용자·권한·작업 상태 추적처럼 Streamlit 구조로는 처음부터 어려웠던
  요구사항을 Spring Boot + MySQL + jobs 테이블 polling 구조로 설계 단계부터
  반영한다.

## 남겨둔 미해결 과제

- 루트 `sources.json`, `Research.py` — `auto-sns/backend-python/.../legacy/`
  로도 옮기지 않았다. V4에서 재사용할지 완전히 폐기할지 아직 결정 안 됨.
- `v3-semi-auto`는 이제 더 이상 개발하지 않고 그대로 보존한다(`versions/v3`에
  이미 실행용 복사본도 남겨뒀다). 앞으로의 개발은 상위 폴더의 `auto-sns`에서
  진행한다.
