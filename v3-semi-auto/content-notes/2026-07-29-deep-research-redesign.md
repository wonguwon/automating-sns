# 딥리서치 단계를 다시 설계하면서 부딪힌 것들 (2026-07-29)

V3의 두 번째 실제 기능("딥리서치" 단계)을 Claude Code와 함께 새로 만들면서 나온 것들 중
일반적인 "AI와 페어 코딩" · "프롬프트 설계" 콘텐츠로 쓸 만한 지점들.

## 1. "떠 있는 프로세스는 파일을 고쳐도 모르는 척한다" — 어제도 겪었는데 오늘 또 겪었다

어제(2026-07-28) "컨텐츠 수집" 단계를 만들 때 이미 한 번 마주쳤던 문제(오래 떠 있는 Streamlit
프로세스가 새로 추가한 함수를 `ImportError`로 못 찾는 것)를 오늘 또 그대로 겪었다. `pipeline_common.py`에
`build_research_prompt`를 추가했는데, 사용자가 이미 띄워놓고 있던 세션에서 정확히 같은 에러가 났다.

같은 실수를 하루 만에 반복했다는 게 포인트다 — "떠 있는 프로세스는 코드를 다시 안 읽는다"는 걸 알고
있어도, 실제로 파일을 몇 번씩 고치다 보면 "지금 보고 있는 이 에러가 새 버그인지, 그냥 프로세스가
오래돼서 그런 건지" 헷갈리는 순간이 온다. 해결은 여전히 같다 — 사용자의 세션은 건드리지 않고, 검증용으로
별도 포트에 새 프로세스를 띄워서 확인한다.

## 2. Streamlit 체크박스 "전체 선택" 버튼을 만들려다 정책 에러를 만났다

RSS 항목 목록에 체크박스 열을 넣고 "전체 선택/해제" 버튼을 붙이려 했다. 가장 직관적인 방법은
"버튼을 누르면 `st.session_state[에디터_키]`를 직접 덮어써서 전부 체크된 것처럼 만들기"였는데,
`streamlit.errors.StreamlitValueAssignmentNotAllowedError: Values for the widget with key
'...' cannot be set using st.session_state`로 막혔다. Streamlit은 이미 화면에 그려진 위젯의
내부 상태를 밖에서 직접 덮어쓰는 걸 막아둔다.

우회는 "그 위젯을 아예 새로 만들기"였다 — 데이터의 기본값(체크 여부)과 위젯의 `key`에 버전 번호를
같이 넣어두고, 버튼을 누르면 그 버전을 1 올리고 `st.rerun()`한다. 그러면 다음 렌더에서는 "이전
위젯의 상태를 바꾸는 것"이 아니라 "새 위젯을 새 기본값으로 그리는 것"이 되어 정책에 걸리지 않는다.
겉보기엔 "같은 체크박스 목록"처럼 보이지만 실제로는 매번 새로 태어나는 위젯이라는 게 핵심.

## 3. 저장해둔 프롬프트가 새 기능을 조용히 막았다 — 사용자가 먼저 알아챘다

GPT 선별 프롬프트에 "마지막으로 성공한 프롬프트를 다음에도 이어서 쓴다"는 저장 기능을 붙인 직후,
후보 결과에 새 필드(`sources` — 병합된 원문 링크 배열)를 요청하는 지시를 프롬프트에 추가했다.
그런데 사용자가 "선별 실행 시 후보 분류 규칙에 이 내용을 넣어둬야 하는 거 아니야?"라고 물었고,
확인해보니 정확히 그 문제였다 — 이미 한 번 저장된 사용자의 커스텀 프롬프트가 코드의 최신 기본값보다
우선 적용되고 있어서, 새로 추가한 지시가 실제로는 한 번도 GPT에 전달되지 않고 있었다.

"마지막 값 재사용" 기능은 사용자 경험엔 좋지만, 그 저장된 텍스트 안에 개발자가 계속 바꿔야 하는
부분(출력 스키마 같은)이 섞여 있으면 정확히 이런 문제가 생긴다. 해결은 프롬프트를 둘로 쪼개는
것이었다 — 사용자가 자유롭게 편집하고 저장해도 되는 부분("계정 페르소나", "선별 기준")과, 코드가
항상 최신으로 유지해야 하는 부분("GPT가 반환할 JSON 필드 목록")을 처음부터 분리하고, 후자는
아예 저장 대상에서 빼서 실행할 때마다 코드의 현재 값을 그대로 붙인다. "사용자 맞춤"과 "시스템이
보장해야 하는 계약"을 같은 텍스트 상자에 두지 않는다는 게 일반화할 수 있는 교훈.

## 4. "실제로 더 깊게 조사하게" 만들고 싶었지만 웹 검색은 쓰지 않기로 했다

"딥리서치"라는 이름과 달리 실제로는 후보의 기사 원문 하나만 읽고 정리하는 수준이었다는 걸 사용자가
지적했다. 가장 쉬운 해결은 GPT에 실제 웹 검색 도구를 붙이는 것이었지만, 뉴스를 다루는 서비스에서는
정확성 리스크가 부담스러워 채택하지 않기로 했다(사용자 판단).

대신 택한 방법은 "이미 신뢰된 자료를 더 활용하기"였다 — GPT 선별 단계에서 같은 사건을 다룬 여러
RSS 기사를 하나의 후보로 병합할 때, 그 병합에 쓰인 링크를 전부 후보에 남겨두고, 딥리서치 단계에서
그 링크들을 모두 원문으로 읽어오게 했다. 새로운 정보를 "찾으러 나가는" 게 아니라 "이미 갖고 있는데
안 쓰고 있던 자료를 마저 쓰는" 방향으로 문제를 재정의한 셈이다. 웹 검색 없이도 "더 깊은 조사"라는
느낌을 실질적으로 만들어낼 수 있었던 사례.
