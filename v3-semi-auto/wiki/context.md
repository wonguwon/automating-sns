# Context

## 프로젝트 목적

SNS 콘텐츠(카드뉴스·릴스) 제작 파이프라인을 자동화하는 프로젝트. 소재 수집부터 딥리서치, 콘텐츠 생성, 렌더링, 캡션 작성까지의 흐름을 다룬다.

## 버전 관계

- **V1**: 최초 구현 버전.
- **V2**: V1 이후 고도화 및 트러블슈팅이 반영된 버전. 완전 자동화 파이프라인 구조.
- **V3**: 완전 자동화의 한계를 반영해 새롭게 설계할 반자동화 버전. 이 저장소가 V3다.
- V1, V2는 과거 스냅샷으로 보존하고 더 이상 변경하지 않는다.
- 현재 개발 대상은 V3뿐이다.

## 현재 상태

- V3 코드는 더 이상 V2 그대로가 아니다 — "컨텐츠 수집"(2026-07-28)에 이어 "딥리서치"(2026-07-29)까지
  두 단계가 "문서 기반으로 각 단계를 독립 실행"하는 구조로 재설계·구현되었다.
- 나머지 4개 단계(콘텐츠 JSON · 표지 이미지 · 콘텐츠 렌더 · 릴스 렌더)는 아직 V2 로직을 그대로 페이지로만
  옮겨온 상태이고, 로직 자체는 다음 작업 대상이다.
- data 폴더와 기존 실행 기록(history 등)은 대부분 손대지 않았다 — 단 `history.json` 기록은 데이터 구조가
  재설계될 때까지 5단계 페이지에서 의도적으로 꺼둔 상태다(자세한 내용은 decisions.md 참조).

## 현재 코드 구조 (2026-07-29 갱신 — "딥리서치" 재설계 반영)

이 절은 코드를 직접 읽고 실행해 확인한 현재 사실이다. V3 설계가 바뀌면 이 절도 다시 갱신해야 한다.

- **실행 진입점**: `streamlit run app.py`. `app.py`는 이제 UI 로직을 직접 담지 않고
  `st.navigation([...], position="top")` 셸만 담당한다 — 상단 네비게이션의 각 버튼이 `pages/*.py` 파일
  하나씩과 매핑된다: `1_컨텐츠_수집.py`, `2_딥리서치.py`, `3_콘텐츠_JSON.py`, `4_표지_이미지.py`,
  `5_콘텐츠_렌더.py`, `6_릴스_렌더.py`. 모든 단계는 여전히 사람이 버튼을 눌러야 실행된다 — 자동 실행/
  스케줄러는 없다.
- **공용 모듈**: `pipeline_common.py`(경로 상수·OpenAI 클라이언트·이미지 생성·딥리서치 프롬프트 등 페이지
  공용 헬퍼 — `pages/*.py`는 각자 다른 `__file__`을 가지므로 경로 계산은 반드시 여기서만 한다),
  `pipeline_state.py`(단계 간 연결 문서 — `data/pipeline/<content_id>.json` 매니페스트에 `candidate`·
  `research_pairs`와 각 단계 산출물 경로 포인터만 얇게 저장해, 이전 단계를 같은 세션에서 이어 실행하지
  않아도 해당 content_id로 다시 열면 이어서 진행할 수 있게 한다).
- **1단계("컨텐츠 수집")는 V2 로직에서 완전히 갈라졌다**:
  - `sources_store.py` + `sources/*.json` — 리소스를 그룹(파일) 단위로 관리한다. 그룹 생성 시 GPT로
    피드 후보를 자동 제안받고(기본 프롬프트 템플릿 제공, 수정 가능) 바로 헬스체크까지 돌려 실제 살아있는
    URL인지 확인한다. 그룹별로 피드 추가/수정/삭제/enabled 토글/헬스체크 가능.
  - "RSS 수집" 버튼이 로드된 그룹의 **enabled 피드에서만** 최근 24시간 항목을 원본 그대로 모아
    `data/rss_collect/<그룹>/<날짜>.json`에 저장하고 화면에 표로 보여준다. GPT 선별(오늘의 카드뉴스
    후보 뽑기)은 이 단계가 아니라 2단계(딥리서치) 첫 섹션으로 옮겨졌다 — 아래 참조.
  - 루트 `sources.json`, `Research.py`는 코드가 그대로 남아있지만 **더 이상 어떤 페이지에서도 호출되지
    않는 고아 상태**다(1단계 UI가 이제 sources_store 기반 그룹만 쓴다). 정리할지 유지할지는 아직 결정
    안 됨.
- **2단계("딥리서치")도 V2 로직에서 완전히 갈라졌다(2026-07-29)** — 페이지 안 세 영역이 번호("1./2./3.")로
  읽는 순서만 안내할 뿐, 실제로는 각각 파일로 연결되어 독립적으로 진행 가능하다:
  - **GPT 선별**: 1단계에서 수집한 RSS 원본 중 체크박스로 고른 항목만 GPT에 보내 카드뉴스 후보로
    정리시킨다. 결과는 RSS 수집과 동일하게 그룹별 폴더 `data/candidates/<그룹>/<날짜>.json`에 저장된다.
    선별 프롬프트는 "계정/독자 + 선별 기준"(사용자가 다이얼로그에서 편집, `data/select_prompt_state.json`에
    영속화되어 다음에도 이어짐)과 "출력 형식 스키마"(코드 고정, 화면에 읽기 전용으로만 노출, 저장 안 됨)로
    분리돼 있다 — 스키마에 필드를 추가해도 사용자가 저장해둔 프롬프트에 막히지 않고 항상 최신으로 적용된다.
  - **후보 선택**: 그룹 + 후보 파일을 골라 후보 하나를 고르면, 후보 자체의 id(`YYYYMMDD-NN`)가 그대로
    `data/pipeline/<id>.json` 매니페스트 키가 된다 — 콘텐츠 ID를 사람이 따로 입력하지 않는다.
  - **딥리서치 실행**: 실제 웹 검색은 하지 않는다. 대신 GPT 선별 시 같은 사건으로 병합된 모든 RSS 원문
    링크를 후보에 `sources` 배열로 저장해두고, 이 단계에서 그 링크들을 전부 원문으로 읽어(`fetch_article_text`
    를 여러 건에 반복 적용) 근거를 보강한다(실제 웹 검색은 뉴스 정확성 리스크가 있어 채택하지 않음).
    조립된 프롬프트는 화면에서 그대로 보여주고 실행 전 수정할 수 있다. 결과는 `data/research/<id>.md` +
    `<id>.pairs.json`으로 저장된다.
  - **저장된 결과 열람**: "지금 선택된 후보"와 무관하게 `data/research/*.md` 중 아무 파일이나 셀렉트박스로
    골라 바로 열어볼 수 있다 — 파일 기반 독립 실행 원칙을 열람에도 그대로 적용한 것.
- **3~6단계(콘텐츠 JSON·표지 이미지·콘텐츠 렌더·릴스 렌더)는 V2 로직을 페이지로만 옮긴 상태**, 내부 로직
  자체는 아직 손대지 않았다:
  - `Generate.py`(content.json 생성 함수 + 표지 이미지 생성 함수를 페이지가 import),
    `Render.py`(Playwright로 card-template.html 캡처 → 캐러셀 4:5 + 스토리 9:16 PNG, subprocess 호출),
    `Render_reel.py`(story PNG + 배경음악을 ffmpeg로 이어붙여 릴스 mp4, subprocess 호출),
    `card-template.html`, `prompt-content-json.md` — 전부 V2 그대로. 3단계는 딥리서치가 만든 `pairs`
    (내용+출처 배열)만 입력으로 쓰고, 마크다운 조사 노트 자체는 읽지 않는다 — 노트는 사람이 읽는 참고용이다.
  - **데이터 저장 위치**: `data/content/<id>.json`(3~4단계 canonical), `assets/cover-<id>.png`(4단계),
    `카드뉴스/<id>/`(5·6단계 산출물). 이 저장소에는 `카드뉴스/`·`assets/` 실제 이미지가 아직 없다 —
    5·6단계 렌더 자체(Render.py/Render_reel.py 실행)는 이 저장소에서 한 번도 확인된 적 없다(playwright
    chromium·ffmpeg 설치 여부 미확인).
  - **`history.json` 기록은 5단계 페이지에서 의도적으로 꺼둔 상태다**(2026-07-28, 사용자 결정) — 데이터
    구조가 다시 잡힐 때 함께 재설계하기로 함. `posted` 필드가 어디서도 읽히지 않는 문제(과거 기록) 자체는
    아직 남아있음.
- **외부 API 의존성**: OpenAI(`OPENAI_API_KEY`, 필수) — 소스 그룹 GPT 자동 채움·GPT 선별·딥리서치·
  content.json 생성에 `gpt-5.5`, 표지 이미지 기본값에 `gpt-image-2`. Volcengine Ark Doubao-Seedream
  (`ARK_API_KEY`, 선택)은 이 저장소 `.env`에 키가 없어 현재 동작하지 않음. 그 외 RSS 피드(이제
  `sources/*.json` 그룹 기준), 딥리서치의 원문 fetch(단순 HTTP GET, 검색 아님), 로컬 `ffmpeg`,
  `card-template.html`의 jsdelivr CDN 폰트 로딩에 네트워크 의존이 있다.
- **content.json에는 caption/hashtags가 이미 포함되어 3단계에서 함께 생성된다.** 루트 `README.md`(V2
  문서 그대로)는 "7단계: 인스타 캡션 별도 생성"을 설명하지만 실제 코드에는 없다 — README가 코드보다
  오래됨(이번 세션에서 갱신 안 함).

## 아직 결정하지 않은 사항

- 루트 `sources.json`/`Research.py`를 완전히 걷어낼지, 당분간 고아 상태로 유지할지.
- 3~6단계(콘텐츠 JSON~릴스 렌더) 내부 로직 자체의 유지/단순화/제거/보류 여부 — 아직 페이지만 옮겼을 뿐
  로직 재검토는 안 함.
- data 폴더 구조, history 중복 판정 방식의 최종 형태(지금은 기록만 임시로 꺼둔 상태).
- 새로운 기술 스택이나 의존성 도입 여부.
