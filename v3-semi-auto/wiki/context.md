# Context

## 프로젝트 목적

SNS 콘텐츠(카드뉴스·릴스) 제작 파이프라인을 자동화하는 프로젝트. 소재 수집부터 딥리서치, 콘텐츠 생성, 렌더링, 캡션 작성까지의 흐름을 다룬다.

## 버전 관계

- **V1**: 최초 구현 버전.
- **V2**: V1 이후 고도화 및 트러블슈팅이 반영된 버전. 완전 자동화 파이프라인 구조.
- **V3**: 완전 자동화의 한계를 반영해 새롭게 설계할 반자동화 버전. 이 저장소가 V3다.
- V1, V2는 과거 스냅샷으로 보존하고 더 이상 변경하지 않는다.
- 현재 개발 대상은 V3뿐이다.

## 현재 상태

- V3 코드는 더 이상 V2 그대로가 아니다 — "컨텐츠 수집"(2026-07-28), "딥리서치"(2026-07-29)에 이어
  "카드뉴스 제작"(2026-07-29)까지 재설계·구현이 끝나, V2 이관분 3~6단계 페이지는 삭제되었다.
- 카드뉴스 제작 페이지는 실제 소재(20260729-02, -06)로 JSON 생성 → 표지 이미지 → 렌더(PNG 16장) →
  인스타 캡션까지 전 구간 실행 검증됨. 릴스 제작 페이지와 템플릿 관리 페이지는 아직 없다(다음 작업).
- data 폴더와 기존 실행 기록(history 등)은 대부분 손대지 않았다 — `history.json` 기록은 데이터 구조가
  재설계될 때까지 의도적으로 꺼둔 상태다(렌더를 새 페이지로 옮기면서도 다시 켜지 않음, decisions.md 참조).

## 현재 코드 구조 (2026-07-30 갱신 — "템플릿 관리"·"릴스 제작" 페이지 추가 반영)

이 절은 코드를 직접 읽고 실행해 확인한 현재 사실이다. V3 설계가 바뀌면 이 절도 다시 갱신해야 한다.

- **실행 진입점**: `streamlit run app.py`. `app.py`는 UI 로직을 직접 담지 않고
  `st.navigation([...], position="top")` 셸만 담당한다 — 상단 네비게이션은 5개 페이지다:
  `1_컨텐츠_수집.py`, `2_딥리서치.py`, `3_카드뉴스_제작.py`, `4_템플릿_관리.py`, `5_릴스_제작.py`.
  V2 이관분이던 구 3~6단계 페이지는 2026-07-29에 삭제됐다. 모든 단계는 여전히 사람이 버튼을
  눌러야 실행된다 — 자동 실행/스케줄러는 없다.
- **공용 모듈**: `pipeline_common.py`(경로 상수·OpenAI 클라이언트·템플릿 목록·딥리서치/카드뉴스 JSON/
  인스타 캡션 프롬프트·이미지 생성 등 페이지 공용 헬퍼 — `pages/*.py`는 각자 다른 `__file__`을 가지므로
  경로 계산은 반드시 여기서만 한다), `pipeline_state.py`(단계 간 연결 문서 — `data/pipeline/<content_id>.json`
  매니페스트에 `candidate`와 각 단계 산출물 경로 포인터만 얇게 저장. `research_pairs` 필드는 과거 데이터
  호환용으로 이름만 남아 있고 더 이상 기록하지 않는다).
- **1단계("컨텐츠 수집")는 V2 로직에서 완전히 갈라졌다**:
  - `sources_store.py` + `sources/*.json` — 리소스를 그룹(파일) 단위로 관리한다. 그룹 생성 시 GPT로
    피드 후보를 자동 제안받고(기본 프롬프트 템플릿 제공, 수정 가능) 바로 헬스체크까지 돌려 실제 살아있는
    URL인지 확인한다. 그룹별로 피드 추가/수정/삭제/enabled 토글/헬스체크 가능.
  - "RSS 수집" 버튼이 로드된 그룹의 **enabled 피드에서만** 최근 24시간 항목을 원본 그대로 모아
    `data/rss_collect/<그룹>/<날짜>.json`에 저장하고 화면에 표로 보여준다. GPT 선별(오늘의 카드뉴스
    후보 뽑기)은 이 단계가 아니라 2단계(딥리서치) 첫 섹션으로 옮겨졌다 — 아래 참조.
  - 루트 `sources.json`, `Research.py`는 코드가 그대로 남아있지만 **더 이상 어떤 페이지에서도 호출되지
    않는 고아 상태**다(1단계 UI가 이제 sources_store 기반 그룹만 쓴다). 정리할지 유지할지는 아직 결정
    안 됨.
- **2단계("딥리서치")도 V2 로직에서 완전히 갈라졌다(2026-07-29)** — 섹션은 읽는 순서 안내일 뿐,
  실제로는 각각 파일로 연결되어 독립적으로 진행 가능하다:
  - **GPT 선별**: 1단계에서 수집한 RSS 원본 중 체크박스로 고른 항목만 GPT에 보내 카드뉴스 후보로
    정리시킨다. 결과는 RSS 수집과 동일하게 그룹별 폴더 `data/candidates/<그룹>/<날짜>.json`에 저장된다.
    선별 프롬프트는 "계정/독자 + 선별 기준"(사용자가 다이얼로그에서 편집, `data/select_prompt_state.json`에
    영속화되어 다음에도 이어짐)과 "출력 형식 스키마"(코드 고정, 화면에 읽기 전용으로만 노출, 저장 안 됨)로
    분리돼 있다 — 스키마에 필드를 추가해도 사용자가 저장해둔 프롬프트에 막히지 않고 항상 최신으로 적용된다.
  - **후보 선택**: 그룹 + 후보 파일을 골라 후보 하나를 고르면, 후보 자체의 id(`YYYYMMDD-NN`)가 그대로
    `data/pipeline/<id>.json` 매니페스트 키가 된다 — 콘텐츠 ID를 사람이 따로 입력하지 않는다.
  - **딥리서치 실행**: 실제 웹 검색은 하지 않는다. 대신 GPT 선별 시 같은 사건으로 병합된 모든 RSS 원문
    링크를 후보에 `sources` 배열로 저장해두고, 이 단계에서 그 링크들을 전부 원문으로 읽어(`fetch_article_text`
    를 여러 건에 반복 적용) 근거를 보강한다(실제 웹 검색은 뉴스 정확성 리스크가 있어 채택하지 않음).
    조립된 프롬프트는 화면에서 그대로 보여주고 실행 전 수정할 수 있다. **산출물은 조사 노트
    `data/research/<id>.md` 하나다**(말미에 `## 출처` 섹션) — pairs 중간 산출물은 2026-07-29에 제거됐고,
    기존 `<id>.pairs.json` 파일들은 과거 데이터로만 남아 있다.
  - **저장된 결과 열람**: "지금 선택된 후보"와 무관하게 `data/research/*.md` 중 아무 파일이나 셀렉트박스로
    골라 바로 열어볼 수 있다 — 파일 기반 독립 실행 원칙을 열람에도 그대로 적용한 것.
- **3페이지("카드뉴스 제작")는 2026-07-29에 새로 만들었다** — 구 3~6단계를 대체하며, 한 페이지 안 여섯
  섹션이 각각 파일로 연결되어 독립 실행 가능하다. 하위 섹션은 셀렉트박스 값 변경만으로 반영되지 않고
  명시적 「선택」 버튼으로 확정해야 사용된다:
  - **딥리서치 결과 선택**: `data/research/*.md` 셀렉트박스 + 「선택」. 확정하면 노트 미리보기와 출처 URL
    목록(매니페스트의 candidate.sources)이 보인다.
  - **템플릿 선택**: `templates/<템플릿명>/` 폴더(= `template.html` + `prompt.md` + `예시/` 세트) 셀렉트박스
    + 「예시」(모달로 예시 이미지 격자 표시) + 「선택」. 현재 템플릿은 "기본" 하나(구 card-template.html +
    prompt-content-json.md를 채널 중립·저작권 안전 버전으로 수정해 이동). prompt.md는 화면에서 읽기 전용 —
    수정은 추후 템플릿 관리 페이지에서.
  - **카드뉴스 JSON 생성**: 확정된 리서치·템플릿 + 계정 정보(브랜드·핸들·독자층, 생성 시 입력·저장 안 함)
    + 선택적 "콘텐츠 방향"으로 사용자 프롬프트를 조립(수정 가능)해 gpt-5.5 실행. 시스템 프롬프트는 템플릿의
    prompt.md 그대로. 결과는 `data/content/<id>.json`(canonical) 저장.
  - **카드뉴스 JSON 선택**: `data/content/*.json` 셀렉트박스(라벨에 표지 헤드라인) + 「보기/편집」(다이얼로그,
    적용 시 파일 반영) + 「선택」.
  - **표지 이미지 생성**: 확정된 content.json의 `cover.image_concept`로 프롬프트 조립(수정 가능) →
    `assets/cover-<id>.png` 저장 + `cover.image` 갱신. 기본 모델 Seedream, GPT Image 2 선택 가능
    (품질 옵션은 GPT Image 2 전용, Seedream 선택 시 비활성).
  - **카드뉴스 렌더**: `Render.py`를 subprocess로 호출(템플릿 html 경로를 세 번째 인자로 전달) →
    `카드뉴스/<id>/`에 캐러셀 4:5 + 스토리 9:16 PNG와 caption.txt·sources.md. **이 저장소에서 playwright
    chromium 렌더 실행이 2026-07-29 처음으로 검증됐다**(20260729-02·-06, 각 16장).
  - **인스타 업로드 설명문구**: 딥리서치 결과를 별도 셀렉트박스로 골라 상세 캡션+해시태그를 생성, 복사용
    코드 블록으로 표시(파일 저장은 안 함, 세션에만 유지).
- **4페이지("템플릿 관리")는 2026-07-30에 추가했다** — `templates/<이름>/` 폴더 세트를 화면에서 새로
  만들어주지 않고, 이미 만들어둔 `template.html`·`prompt.md`·예시 이미지를 업로드해서 추가/교체하는
  파일 관리 페이지다. 목록은 셀렉트박스로 고르고 「예시」/「프롬프트」 버튼으로 각각 모달 확인. 편집은
  파일 재업로드로 덮어쓰기, 삭제는 이름 재입력 확인 후 폴더 전체 삭제.
- 같은 날 "기본" 템플릿의 표지/CTA 이미지가 evidence 박스로 중복 렌더링되던 버그를 수정했다
  (`renderDefaultBody`가 `isEdge` 슬라이드도 구분 없이 evidence를 그리던 문제 — 같은 이미지가 전체화면
  배경과 작은 썸네일로 두 번 그려지고, 그 여분 박스가 본문 높이를 부풀려 텍스트가 하단 스크림 밖으로
  밀려나는 부작용까지 있었다).
- **5페이지("릴스 제작")는 2026-07-30에 새로 만들었다** — 딥리서치 결과 선택 → 대본 생성(GPT,
  나레이션 단독 + 사실 기반 조사 노트 + 사용자 "방향성/의견" 입력을 결합, 대사 100~150자·6~10줄
  내외로 압축, 대화체·대본 예시 참고는 시도해보고 제거함) → 장면 이미지 준비(대본이 지목한
  장면 2~4개를 사진 라이브러리에서 재사용하거나 없으면 Seedream/GPT Image로 생성) → TTS 생성
  (타입캐스트, 목소리는 "민욱" 고정·속도(0.5~2.0배속)·감정(자동/직접 지정) 조절 가능) → 릴스
  조립(`Render_reel_narrated.py`, 장면별 zoompan 줌인/줌아웃/패닝 효과 + 상단 2줄 제목(1번째
  흰색·2번째 강조 노란색)·하단 자막(굵게, 길면 자동 2줄) 레터박스 레이아웃). 실제 소재로 대본
  생성→장면 이미지→TTS→조립 전 구간 실행 검증됨. 사진 라이브러리(`assets/reel_photos/`)는 이
  페이지가 아니라 별도로 관리한다. 목소리 셀렉트박스(여러 목소리 중 선택)는 아직 없음.
- **`Render_reel.py`(고정 길이 배경음악 전용 구 릴스 조립기)는 여전히 어느 페이지에서도 호출되지
  않는다** — 릴스 제작은 위처럼 `Render_reel_narrated.py`(대사 길이 기반, 신규)를 쓴다. ffmpeg는
  이 저장소에 설치돼 있고 실제로 검증됨(2026-07-30).
- **`history.json` 기록은 여전히 꺼진 상태다**(2026-07-28 결정) — 렌더를 새 페이지로 옮기면서도 다시 켜지
  않았다. `posted` 필드가 어디서도 읽히지 않는 문제(과거 기록)도 그대로.
- **외부 API 의존성**: OpenAI(`OPENAI_API_KEY`, 필수) — 소스 그룹 GPT 자동 채움·GPT 선별·딥리서치·
  카드뉴스/릴스 대본 JSON·인스타 캡션에 `gpt-5.5`, 표지·장면 이미지 선택지에 `gpt-image-2`.
  Volcengine Ark Doubao-Seedream(`ARK_API_KEY`)이 표지·장면 이미지 기본값이며 실제 생성 호출까지
  검증됨(2026-07-30). 타입캐스트(`TYPECAST_API_KEY`, TTS)도 실제 음성 목록 조회·합성 호출까지
  검증됨(2026-07-30). 그 외 RSS 피드(`sources/*.json` 그룹 기준), 딥리서치의 원문 fetch(단순 HTTP
  GET, 검색 아님), 로컬 `ffmpeg`(릴스 조립용, 설치·실사용 검증됨), 템플릿 html의 jsdelivr CDN 폰트
  로딩에 네트워크 의존이 있다.
- **content.json에는 caption/hashtags가 포함되지만**(렌더 시 caption.txt로 저장), 인스타 업로드용 상세
  캡션은 별도 섹션에서 조사 노트로부터 다시 생성한다. 루트 `README.md`는 여전히 V2 문서 그대로라 현재
  구조와 크게 다르다(미갱신).

## 아직 결정하지 않은 사항

- 루트 `sources.json`/`Research.py`를 완전히 걷어낼지, 당분간 고아 상태로 유지할지. `Generate.py`의
  CLI 경로(main 함수)와 `generate_content_json`도 이제 페이지에서 쓰지 않아 부분 고아가 됐다.
- data 폴더 구조, history 중복 판정 방식의 최종 형태(지금은 기록만 임시로 꺼둔 상태).
- 인스타 캡션을 파일로 저장할지(지금은 세션에만 유지).
- 릴스 제작의 남은 세부사항: 타입캐스트 목소리 셀렉트박스(현재 "민욱" 고정), 릴스 사진
