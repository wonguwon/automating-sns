# Roadmap

기능별 유지·제거 결정은 아직 내리지 않는다. 아래 단계 순서로만 진행한다.

1. V2 현재 구조 파악 — 완료 (2026-07-27, 코드 분석 결과는 [context.md](context.md) "현재 코드 구조" 절 참조)
2. V3에서 해결할 핵심 문제 정의 — 완료 (2026-07-28, 결론: 문서 기반 독립 실행 + 리소스 그룹 관리로 방향 확정, [decisions.md](decisions.md) 참조)
3. V3 최소 사용자 흐름 결정 — 완료 (2026-07-28, 6단계를 각각 별도 페이지로 분리, `data/pipeline/<content_id>.json`로 연결)
4. 기존 기능을 유지·단순화·제거·보류로 분류 ← 진행 중 (1단계 "컨텐츠 수집", 2단계 "딥리서치" 재설계 완료, 나머지 4단계는 V2 로직 그대로 옮긴 상태)
5. 첫 번째 최소 기능 구현 — "컨텐츠 수집" 단계 완료 (2026-07-28, 리소스 그룹 관리 + RSS 수집)
6. 두 번째 기능 구현 — "딥리서치" 단계 완료 (2026-07-29, GPT 선별 + 후보 선택 + 다중 출처 딥리서치 + 파일 기반 결과 열람)
7. 실제 사용 후 개선 ← 다음 단계

## 다음으로 할 일 (우선순위 순)

- 남은 4개 단계(콘텐츠 JSON·표지 이미지·콘텐츠 렌더·릴스 렌더)를 "컨텐츠 수집"·"딥리서치"와 같은 방식으로 하나씩 재검토.
- 루트 `sources.json`/`Research.py`(현재 고아 상태) 정리 여부 결정.

각 단계가 끝나고 장기적으로 유효한 결정이 생기면 [decisions.md](decisions.md)에 기록하고, 다음 단계로 넘어가기 전에 이 문서를 갱신한다.
