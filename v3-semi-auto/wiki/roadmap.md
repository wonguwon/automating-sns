# Roadmap

기능별 유지·제거 결정은 아직 내리지 않는다. 아래 단계 순서로만 진행한다.

1. V2 현재 구조 파악 — 완료 (2026-07-27, 코드 분석 결과는 [context.md](context.md) "현재 코드 구조" 절 참조)
2. V3에서 해결할 핵심 문제 정의 — 완료 (2026-07-28, 결론: 문서 기반 독립 실행 + 리소스 그룹 관리로 방향 확정, [decisions.md](decisions.md) 참조)
3. V3 최소 사용자 흐름 결정 — 완료 (2026-07-28, 6단계를 각각 별도 페이지로 분리, `data/pipeline/<content_id>.json`로 연결)
4. 기존 기능을 유지·단순화·제거·보류로 분류 — 완료 (2026-07-29, V2 이관분 구 3~6단계 페이지는 삭제하고 "카드뉴스 제작"으로 재구성. Generate/Render/Render_reel 로직은 재사용용으로 유지)
5. 첫 번째 최소 기능 구현 — "컨텐츠 수집" 단계 완료 (2026-07-28, 리소스 그룹 관리 + RSS 수집)
6. 두 번째 기능 구현 — "딥리서치" 단계 완료 (2026-07-29, GPT 선별 + 후보 선택 + 다중 출처 딥리서치 + 파일 기반 결과 열람. 같은 날 pairs 중간 산출물을 제거하고 조사 노트 단일 산출물로 단순화)
7. 세 번째 기능 구현 — "카드뉴스 제작" 페이지 완료 (2026-07-29, 리서치 선택 → 템플릿 세트 선택 → JSON 생성(계정 정보·콘텐츠 방향 입력) → 표지 이미지(Seedream 기본) → 렌더(playwright 실검증) → 인스타 캡션. 실제 소재 2건으로 전 구간 실행 확인)
8. 실제 사용 후 개선 ← 진행 중

## 다음으로 할 일 (우선순위 순)

- 릴스 제작 페이지 — 딥리서치/카드뉴스 산출물을 입력으로 받는 새 페이지 구성 (`Render_reel.py` 재사용 여부 검토, ffmpeg 미검증).
- 템플릿 관리 페이지 — 템플릿 세트(html + prompt.md + 예시 이미지) 추가/편집 UI.
- 고아 파일 정리 여부 결정 — 루트 `sources.json`/`Research.py`, `Generate.py`의 CLI 경로, V2 기준 `README.md` 갱신.

각 단계가 끝나고 장기적으로 유효한 결정이 생기면 [decisions.md](decisions.md)에 기록하고, 다음 단계로 넘어가기 전에 이 문서를 갱신한다.
