# Decisions

이 문서는 장기적으로 유지될 확정 결정만 기록한다. 임시 아이디어나 검토 중인 옵션은 여기 적지 않는다.

## 확정된 결정

- V1과 V2는 과거 스냅샷으로 보존한다. 더 이상 수정하지 않는다.
- 신규 개발은 V3(`v3-semi-auto`, 이 저장소)에서 수행한다.
- V3는 완전 자동화가 아닌 반자동화 방향으로 새롭게 설계한다.
- V3는 V2 코드를 출발점(복제본)으로 사용한다.
- V3 설계가 확정되기 전에는 기존 `data` 폴더와 history 기록을 변경하지 않는다.
- 위키(`wiki/`)에는 장기적으로 유지될 사실과 결정만 기록한다. 새로운 기술 선택이나 기능 유지 여부는 실제로 결정된 뒤에만 여기 추가한다.
- V3는 파이프라인을 순차 "단계" UI가 아니라, 문서(파일) 기반으로 각 단계를 독립 실행 가능하게 재설계한다. `data/pipeline/<content_id>.json` 매니페스트가 단계 간 연결 문서 역할을 한다(2026-07-28).
- 소스(피드) 관리는 그룹 단위(`sources/*.json`)로 한다. 그룹 생성 시 GPT로 피드 후보를 자동 제안받고 헬스체크로 실제 URL 여부를 검증할 수 있다(2026-07-28).
- history.json 기록은 데이터 구조가 재설계될 때까지 임시로 끈다 — 어차피 구조를 다시 잡을 예정이라 지금 형태로 계속 기록하지 않는다(2026-07-28, 5단계 콘텐츠 렌더 페이지에 적용).
- 딥리서치 단계는 콘텐츠 ID를 사람이 직접 입력하지 않는다 — GPT 선별이 만든 후보 자체의 id(`YYYYMMDD-NN`)를 그대로 파이프라인 식별자로 쓴다(2026-07-29).
- GPT 선별 결과도 RSS 수집과 동일하게 그룹별 폴더(`data/candidates/<그룹>/<날짜>.json`)에 저장한다(2026-07-29).
- 딥리서치는 실제 웹 검색을 하지 않는다 — 대신 GPT 선별 시 같은 사건으로 병합된 모든 RSS 원문 링크를 후보에 저장해두고(`candidate["sources"]`), 딥리서치 단계에서 그 링크들을 전부 원문으로 읽어 근거를 보강한다. 실제 웹 검색은 뉴스 정확성 리스크가 있어 채택하지 않는다(2026-07-29).
- GPT 선별 프롬프트는 "계정/독자 + 선별 기준"(사용자 편집, `data/select_prompt_state.json`에 영속화)과 "출력 형식 스키마"(코드 고정, 항상 최신 적용, 저장하지 않음)로 분리한다 — 사용자가 저장해둔 프롬프트가 스키마 변경을 가로막는 문제를 막기 위함(2026-07-29).
- 딥리서치 프롬프트도 화면에서 그대로 보여주고 실행 전 수정할 수 있게 한다(원문 fetch → 자동 조립 → 편집 가능, 2026-07-29).
- 페이지 내 하위 섹션 번호("1.", "2.", "3.")는 읽는 순서 안내일 뿐 강제 순서가 아니다 — 각 섹션은 파일로 연결되어 독립적으로 진행 가능하므로 UI 라벨에서 번호를 뺀다. 딥리서치 결과 열람도 "현재 선택된 후보"와 무관하게 저장된 파일 중에서 바로 고를 수 있다(2026-07-29).
- 딥리서치 프롬프트에는 저작권 안전장치를 명시한다 — 사실(숫자·날짜·기관명·발언 요지)은 정확히 유지하되 원문 문장을 그대로(또는 어순만 바꿔) 옮기지 않고 새로 쓰게 하며, 직접 인용이 필요하면 따옴표로 표시하고 화자를 밝히게 한다(2026-07-29).
- V2에서 이관만 해뒀던 3~6단계 페이지(콘텐츠 JSON·표지 이미지·콘텐츠 렌더·릴스 렌더)는 삭제하고, 딥리서치 결과를 입력으로 받는 "카드뉴스 제작" 페이지(추후 "릴스 제작" 페이지)로 재구성한다. `Generate.py`/`Render.py`/`Render_reel.py`의 로직은 재사용을 위해 남긴다(2026-07-29).
- 카드뉴스 템플릿은 `templates/<템플릿명>/` 폴더에 `template.html`(렌더·글자수 검증) + `prompt.md`(JSON 생성 규칙) + `예시/`(예시 이미지)를 한 세트로 관리한다 — HTML의 LIMITS 검증과 프롬프트의 글자수 규칙은 같은 스키마의 양면이라 분리하지 않는다. 템플릿 추가/관리 페이지는 카드뉴스 제작 흐름 완성 후 별도로 만든다(2026-07-29).
- 템플릿과 프롬프트는 특정 채널(구 칼퇴각)에 고정하지 않는다(채널 중립). 계정 정보(브랜드·핸들·독자층)는 카드뉴스 생성 시 화면에서 입력하며 파일로 저장하지 않는다(2026-07-29).
- 콘텐츠 생성은 "사실·형식은 고정, 스토리라인·문구는 GPT 재량"으로 한다 — "무엇이 발표됐나 → 왜 중요한가 → …" 같은 고정 흐름 강제를 프롬프트에서 제거하고, 소재별로 GPT가 스토리라인·eyebrow 라벨을 직접 설계한다. 원하는 방향이 있을 때만 선택 입력 "콘텐츠 방향"으로 지시한다(2026-07-29).
- 딥리서치의 pairs 중간 산출물(`<id>.pairs.json`, `---PAIRS---` 출력)은 제거한다 — 조사 노트(마크다운, 말미에 `## 출처` 섹션)가 유일한 산출물이고, 카드뉴스 생성은 노트 전문 + 후보(candidate)의 출처 URL 목록을 입력으로 쓴다. 실데이터에서 사실↔출처 매핑이 소재 단위(같은 URL)로 수렴해 쌍 구조의 실익이 없었기 때문. 카드 슬라이드별 출처 표시는 그대로 유지한다(출처는 URL 목록에서 선택). 기존 `.pairs.json` 파일과 매니페스트의 `research_pairs` 필드는 과거 데이터 호환용으로만 남긴다(2026-07-29).
- 저작권 안전장치는 딥리서치뿐 아니라 카드뉴스 JSON 생성·인스타 캡션 생성 프롬프트에도 동일하게 명시한다 — 기사 제목·문장 재사용 금지, 전 문장 새로 쓰기, 직접 인용 시 따옴표+화자, 출처 표기 유지(2026-07-29).
- 표지 이미지 기본 생성 모델은 Doubao-Seedream(Volcengine Ark, `ARK_API_KEY` 필요)이며, GPT Image 2는 선택지로 유지한다. 품질 옵션은 GPT Image 2 전용이라 Seedream 선택 시 비활성화한다(2026-07-29).
- 셀렉트박스 값이 바뀌는 것만으로는 다음 섹션에 반영하지 않는다 — 명시적 「선택」 버튼으로 확정한 대상만 하위 섹션(표지 이미지·렌더 등)이 사용한다. 리서치/템플릿/카드뉴스 JSON 선택 모두 동일한 패턴을 쓴다(2026-07-29).
