# 이미지가 "2장처럼" 보인다는 피드백 — 실제 렌더 결과를 보고서야 찾은 버그

사용자 피드백: 표지 이미지가 하나 들어가는데 마치 2장처럼 보인다. 그리고 텍스트 가독성을 위해 일부러 넣은 하단 어두운 스크림이, 텍스트가 위로 올라가니까 정작 안 보인다.

두 가지 별개 증상처럼 들렸지만, `template.html` 코드만 읽어서는 원인이 바로 보이지 않았다. 실제로 이미 렌더돼 있던 카드뉴스 PNG(`카드뉴스/20260729-02/carousel/01.png`)를 열어보고 나서야 문제가 눈에 들어왔다 — 배경 사진 위에 같은 사진의 작은 둥근 썸네일이 겹쳐 그려져 있었다.

## 원인

`renderDefaultBody()`가 `slide.image`가 있으면 무조건 작은 `.evidence` 박스(둥근 썸네일)를 본문에 그리는데, 표지·CTA 슬라이드는 이미 같은 이미지를 전체화면 배경(`.bg-photo`)으로 쓰고 있었다. 같은 필드(`cover.image`)를 두 군데서 중복 사용한 것이 원인. 게다가 이 여분 박스(최대 460px 높이)가 본문 블록 전체 높이를 부풀려서, 하단 정렬(`justify-content:flex-end`)되는 헤드라인·부제가 실제로는 화면 하단이 아니라 중간쯤으로 밀려 올라갔다 — 그래서 정작 가장 어두운 스크림 구간(하단 96%)을 벗어나 텍스트 가독성 문제까지 같이 생겼다.

즉 겉으로는 "이미지 중복"과 "텍스트 위치/가독성" 두 문제처럼 보였지만 뿌리는 하나였다.

## 교훈

코드를 읽는 것만으로는 이 버그가 잘 보이지 않았다 — `renderDefaultBody`와 `hasPhoto`/`bg-photo` 로직이 서로 다른 함수에 나뉘어 있어서, 각각은 정상으로 보였다. 실제 산출물(스크린샷)을 열어보고 나서야 두 로직이 같은 이미지 필드를 놓고 겹치고 있다는 게 명확해졌다. "실제 실행 결과를 최우선으로 판단한다"는 원칙이 실전에서 왜 중요한지 보여주는 구체적 사례.

## 수정

`renderDefaultBody`의 evidence 조건에 `!slide.isEdge`를 추가 — 표지/CTA(`isEdge`)는 evidence 박스를 그리지 않도록 한 줄만 고쳤다. 실제 소재로 재렌더해 중복 썸네일이 사라지고 텍스트가 스크림 구간 안으로 돌아온 것을 확인했다.
